# CLAUDE.md

Guidance for Claude Code (and other AI assistants) working in this repository.

## What this repo is

**Swarajya: Shivaji's Legacy** — a real-time "bullet-heaven" action game
grounded in 17th-century Maratha history. Drive a historical commander
(Shivaji Maharaj, Tanaji Malusare, Bajiprabhu Deshpande, or Netaji Palkar)
around a real-time arena with a virtual joystick, auto-attacking weapons
fight off waves of Mughal/Adilshahi forces, and picking up dropped
Valor/Swarajya (Hon) levels you up mid-run. Each ~3-minute campaign banks
Swarajya into **Raigad Fort**, the persistent hub between runs, where you
upgrade the Armory, unlock weapons, chase achievements, and "Renew the Oath"
to prestige for a permanent run multiplier.

Plain HTML/CSS/JavaScript with **no build step, no bundler, no framework**.
Packaged as an Android app for the Play Store via
[Capacitor](https://capacitorjs.com/), which wraps `game/` unmodified.

The game was reskinned from an earlier "Blade Hunter" sci-fi theme into this
Maratha-history theme — you'll see old internal identifiers survive on
purpose (see Conventions below). Historical content is handled deliberately:
real forts/weapons/companions are named, but enemies are generic ranks
(Mughal Scout, Adilshahi Skirmisher, ...) rather than named historical
individuals, so no real person becomes a repeatable video-game kill. Keep
that line if you add content.

## Repository layout

```
game/                 The entire game — open game/index.html directly in a browser to play/dev
  index.html            Script tags define load order (see below) — order matters
  css/style.css
  js/                   Plain-script modules, no bundler (see Conventions)
  assets/characters/    Hand-illustrated companion sprites (SVG source + rasterized PNG)
android/              Generated by `npx cap add android` — standard Capacitor Android/Gradle project.
                      Do not hand-edit generated files; re-run `npx cap sync` instead.
store-assets/         Master icon art (icon-source.svg) + Play Store export-size checklist
docs/                 Play Store publishing checklist (PUBLISHING.md) + privacy policy draft
capacitor.config.json  App id, splash screen, AdMob config
package.json          Capacitor CLI scripts only — no bundler/lint/test scripts
.github/workflows/android-build.yml   CI: builds a debug APK on every push
```

## Local development

No build tooling needed for the game itself:

```bash
open game/index.html            # macOS
xdg-open game/index.html        # Linux
# or, recommended (some browsers restrict localStorage under file://):
npx http-server game -p 8080    # then visit http://localhost:8080
```

Any change under `game/` is live immediately on reload — there is no
compile/transpile step to run or forget.

## Building the Android app

```bash
npm install                # installs @capacitor/* + admob plugin
npx cap add android         # first time only — generates android/
npx cap sync                 # run after every change to game/ — copies web assets into android/
npx cap open android         # opens Android Studio to build/run/sign
# or, from the CLI:
cd android && ./gradlew assembleDebug
```

CI (`.github/workflows/android-build.yml`) does exactly this sequence
(`npm ci` → add android platform if missing → `npx cap sync` →
`gradlew assembleDebug --no-daemon`) and uploads the debug APK as a build
artifact on every push/PR. There are no other CI jobs — no lint step, no
automated test suite exists for the JS game code today.

**Before a real store release** (not needed for local dev/testing), these
placeholders must be replaced — see `README.md` for the full list:
`appId` in `capacitor.config.json` (currently `com.bladehunter.idle`, a
leftover from the pre-reskin app — changing it is permanent once published
and also requires updating `android/app/build.gradle`'s `applicationId` and
`MainActivity.java`'s package path), a real AdMob App ID/Ad Unit ID (in
`capacitor.config.json`, `AndroidManifest.xml`, and `game/js/ads.js`, plus
flipping `AdMob.initializeForTesting` to `false`), a signing keystore
(never commit — already gitignored), and a hosted privacy policy URL.

## Architecture notes

- **Global namespace, one file per system.** Every module attaches itself to
  a shared `window.Game` object: `Game.State`, `Game.Arena`, `Game.Weapons`,
  `Game.Enemies`, `Game.Pickups`, `Game.Player`, `Game.Camp`, `Game.Prestige`,
  `Game.Achievements`, `Game.Ads`, `Game.Save`, `Game.Joystick`, `Game.UI`,
  `Game.UICamp`, `Game.UIHunt`, `Game.Utils`. There is no module
  loader/bundler — **script tag order in `game/index.html` IS the dependency
  order**. If you add a new `js/` file or reorder a `<script>` tag, make sure
  everything that references `Game.X` loads after `X`'s own script.
- **Module pattern:** each file is `Game.Foo = (function () { ...; return
  {...}; })();` — an IIFE exposing a small public surface (functions, and
  occasionally an ES5 getter like `state.js`'s `get data()`), with constants
  and helpers kept private inside the closure. Match this pattern for new
  systems rather than introducing classes, ES modules, or a different style.
- **Two-phase gameplay loop:** **Camp** (`camp.js`, `ui-camp.js` — Raigad
  Fort hub: armory upgrades, prestige, achievements) and **Hunt**
  (`arena.js`, `ui-hunt.js`, `enemies.js`, `weapons.js`, `pickups.js`,
  `joystick.js` — the real-time ~3-minute run). `main.js` is the entry point:
  boots `Game.State`/`Game.UI`, applies offline-earnings, and wires up
  autosave (10s interval, plus on `visibilitychange`/`pagehide`/Capacitor
  `appStateChange`).
- **`arena.js` is the largest file (~900 lines)** — the run's game loop
  (movement, collision, weapon firing, enemy AI ticks, rendering). If it's
  fixed logic (rates, growth curves, thresholds) prefer adding to a `DEFS`/
  const table near the top of the relevant file over inline magic numbers,
  matching the existing weapon/enemy definitions.
- **Save system:** `localStorage` key `bladeHunterIdle_save_v1` — **do not
  rename**, even though it says "bladeHunter" and the game is now Swarajya;
  renaming silently wipes every existing player's save for no player-visible
  benefit (the key is never shown to the player). `Game.State.reconcile()`
  merges a loaded save over `createDefault()` field-by-field so new fields
  never crash on an old save, bumps `SAVE_VERSION`, and explicitly `delete`s
  fields from the old pre-v3 tap-clicker schema. **When adding a new
  persisted field, add it to `createDefault()` and, if old saves need
  cleanup, to `reconcile()`; bump `SAVE_VERSION` only for schema changes that
  need active migration.**
- **Ads are opt-in only** (`game/js/ads.js`) — three rewarded-video
  placements (War Preparation, Revive, Double Rewards), never interstitials
  or banners, never forced. In a plain browser (no Capacitor/AdMob), ad
  buttons render disabled so the game stays fully playable ad-free during
  development — preserve that fallback if you touch `ads.js`.
- **No network calls, no accounts.** Everything is local-device state. Keep
  new features consistent with that — this is not a backend-connected game.

## Conventions

- **Internal IDs vs. display names are deliberately decoupled post-reskin.**
  Weapon/character/enemy *internal keys* (`bladeAcolyte`, `shadowBlade`,
  `riftTurret`, `bladeHunter`) are leftover sci-fi names from before the
  Maratha-history reskin; their `name:`/display fields carry the real
  in-game names ("Talwar Strike", "Wagh Nakh Throw", "Watch Tower Archer").
  **Do not rename internal keys to match the theme** — that's a save-data
  migration with no player-visible benefit, same reasoning as the
  `localStorage` key above. Only add/change the human-facing `name`/label
  fields and comments.
- **Definition tables over scattered constants.** New weapons go in
  `Game.Weapons`'s `DEFS` object (see `weapons.js`) with the same shape as
  existing entries (`kind`, `baseDamage`, `damageGrowth`, cooldown/range
  fields, level-up bonus arrays); new enemies follow the equivalent pattern
  in `enemies.js`. Keep numeric balance changes isolated to these tables.
  Comments in `weapons.js` document *why* a value/behavior was chosen
  (readability, visual-hit-area matching, etc.) — keep that practice for
  non-obvious balance/behavior decisions.
- **No semicolon-optional or exotic JS features** — this codebase is plain
  ES5/ES6-ish function-based JS (`function () {}`, `var`/`const`/`let` mixed
  per file, `Object.assign`, `Array.prototype.forEach`), no async/await, no
  classes, no JSX/TS. Match the existing style rather than introducing a
  more modern idiom in one file only.
- **Never commit secrets or generated build output**: `android/app/build/`,
  `android/build/`, `android/.gradle/`, `android/local.properties`,
  `*.keystore`/`*.jks` are gitignored — keep it that way. `android/` itself
  IS committed (it's the generated-but-tracked Capacitor project — don't
  `.gitignore` it wholesale, only its build output).
- **History content guardrail:** named companions/forts/weapons stay
  historically grounded and respectful; enemy units stay generic ranks, not
  named historical figures. Apply this when adding new content (new
  companions, weapons, enemy types, or copy).
